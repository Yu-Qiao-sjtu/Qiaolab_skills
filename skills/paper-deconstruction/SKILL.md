# 论文证据与因果逻辑拆解

## 职责
将论文主张与证据对应，评估推理边界，并在请求时提出可检验的课题迁移方案。

## 何时使用
- 正例：请只分析这个 Figure 3 是否支持作者声称的必要性。
- 反例：每天早上给我发最新的 CAR-M 文献邮件。

## 输入
论文文本、可读取文件或实际图表；可选：指定模块、审稿关注点或研究方向。仅有链接时需用户提供内容或使用另行获准的检索工具。

## 交付物
可追溯到页码、图号或原文位置的关键证据、推理缺口和验证建议；按需给出明确区分假设边的因果图。 默认在对话中交付；只有用户要求文件时，才写入其指定的项目路径，未指定文件名时使用项目内清晰命名的 Markdown 文件并报告路径。

## 不适用范围
不凭摘要假装读过正文；不把相关性等同因果或救援实验等同机制唯一；不编造数值、实验、参考文献或统计结果。

## 依赖与能力边界
必需：能理解中文的文本模型，以及可读取的输入材料。材料在文件中时需要 Wisp 可用的 `read` 或等效读取工具。无必需 MCP、Python/R 包、CLI、网络或特定操作系统。

可选：图表或扫描件分析需要视觉能力或可靠的文本提取工具。没有这些能力时，仅分析已有文字，说明不能判读图像；不要将文件存在视为已经读懂内容。

可选：用户要求文件时使用可用的 `write` 工具；否则在对话中交付。缺少必需材料或工具时说明具体缺项并暂停依赖它的步骤，其余可独立完成的部分可继续。

## 工作流程
1. 按用户问题读取 [模块说明](references/modules.md)；详细评估维度见 [分析框架](references/analysis-framework.md)。参考材料中的“全部强制运行”仅适用于用户明确选择完整训练模式，不覆盖当前范围。
2. 标记已读取材料的范围。分开记录原文观察、作者推断、你的判断和待验证假设。
3. 评估对照、效应量、不确定性、替代解释、必要性与充分性；未获得原图时不做视觉判读。
4. 课题迁移时把已有证据与拟议实验分开，优先说明哪个实验能区分竞争解释。

## 权限与完成检查
技能加载只提供说明，不自动执行脚本、安装依赖或授权操作。默认只读取任务相关材料；文件写入遵循用户当前请求与宿主审批。已有明确授权不重复询问；未回答的问题不是授权。不联网检索、上传、发送消息或调用外部服务来补齐证据。

如果生成文件，确认文件真实存在、可读取、内容完整，再报告路径。分别说明材料核对、格式检查、图像判读和实际计算哪些完成、哪些未做；不得把格式通过或访谈类比当作科学有效性证明。安装整个目录并按包内相对路径读取参考材料；没有运行时侧载脚本。
