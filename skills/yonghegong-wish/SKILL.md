# 目标与指令精确表达

## 职责
用“指令被字面执行”的反例检查，帮助用户把模糊愿望改写为可验收的要求。

## 何时使用
- 正例：这条需求只写了“越快越好”，帮我补成不会跑偏的可验收描述。
- 反例：帮我算一下去雍和宫许愿能否成功。

## 输入
原始目标、指令或需求；可选：预期结果、禁止事项与资源约束。

## 交付物
歧义清单、改写版本、验收标准和可暴露误解的反例。 默认在对话中交付；只有用户要求文件时，才写入其指定的项目路径，未指定文件名时使用项目内清晰命名的 Markdown 文件并报告路径。

## 不适用范围
不将故事或评论案例视为超自然因果证据；不代替法律专业审查，不添加用户未要求的功能。

## 依赖与能力边界
必需：能理解中文的文本模型，以及可读取的输入材料。材料在文件中时需要 Wisp 可用的 `read` 或等效读取工具。无必需 MCP、Python/R 包、CLI、网络或特定操作系统。

可选：用户要求文件时使用可用的 `write` 工具；否则在对话中交付。缺少必需材料或工具时说明具体缺项并暂停依赖它的步骤，其余可独立完成的部分可继续。

## 工作流程
1. 需要方法或反例时读取 [精确表达框架](references/methods.md)；其中故事是说明歧义的比喻，不是事实保证。
2. 逐项标记对象、条件、范围、时间、禁止项和成功标准中缺失的内容。
3. 给出保留原意的改写；缺失的必要参数标为待确认，不擅自选定业务目标。
4. 用一个可能“字面满足但违背意图”的反例检验改写是否充分。

## 权限与完成检查
技能加载只提供说明，不自动执行脚本、安装依赖或授权操作。默认只读取任务相关材料；文件写入遵循用户当前请求与宿主审批。已有明确授权不重复询问；未回答的问题不是授权。不联网检索、上传、发送消息或调用外部服务来补齐证据。

如果生成文件，确认文件真实存在、可读取、内容完整，再报告路径。分别说明材料核对、格式检查、图像判读和实际计算哪些完成、哪些未做；不得把格式通过或访谈类比当作科学有效性证明。安装整个目录并按包内相对路径读取参考材料；没有运行时侧载脚本。
